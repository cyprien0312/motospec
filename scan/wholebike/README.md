# 整车扫描（未拆解）能拿到什么 —— Yamaha R3 实测

`SCAN_WORKFLOW.md` 第三节第一句是"拆掉 —— 优先做这个"。这个目录记录的是**没拆**
的情况下，一台带整流罩的整车扫描到底能拿到哪些数、拿不到哪些数，以及每个数是怎么
验证的。结论：**前端几何可以拿到，且精度足够；连杆级的点一个也拿不到。**

样本：`geo-R.ply`（Creality Otter Lite，几何模式高精度，4 次扫描在 CloudCompare
里合成），598,298 点。

`diag.py` 复现这一节。

> **合并多次扫描时，第一件事是查有没有双层壳。** 两遍配准差 0.1~0.3mm 会让半径
> 拟合系统性偏大，而点云看起来完全正常。这个文件通过了。

### 双层壳怎么正确地查

用最近邻距离查**不管用** —— 它被完全重复点主导（两个文件都有 ~32% 重复点，
NN 中位数直接是 0）。正确做法是看**局部表面沿法向的残差分布**：单层壳单峰，
双层壳会在 0 处凹陷、两侧各一个峰（`shell.py`）。

| | 0 处密度 / 峰值 | 判定 |
|---|---|---|
| `geo-R.ply` | 0.994 | 单峰 → **单层壳** |
| `dot-r.ply` | 0.999 | 单峰 → **单层壳** |

两个都干净。

## 二、拿到的数（附验证）

坐标系：**原点 = 后轮触地点，+X 向前，+Y 向左，+Z 向上，mm**。

| 量 | 实测 | 官方 | 怎么验证的 |
|---|---|---|---|
| 后轮心 | (0, 0, 286.7) | — | 轮辋 r≈216 **360° 全覆盖** |
| 前轮心 | (1411.2, 2.4, 294.8) | — | Y=2.4mm，落在中面上 |
| 轴距 | **1411.2** | 1380 | 见下"为什么多 31mm" |
| **rake** | **25.49°** | **25.0°** | 两根前叉管独立拟合，差 **0.02°** |
| 前叉管半径 | 21.16 / 21.23 mm | 41mm 外径 | ✅ |
| 前叉管间距 | 211.0 mm | ~210 | ✅ |
| 前叉对中点 Y | **0.11 mm** | 应为 0 | ✅ 见下 |
| 后轮辋半径 | 216 | 17″ = 215.9 | ✅ **绝对尺度验证** |
| 后胎面半径 | 314 | — | 胎侧 314−216 = **98mm** |
| 后胎规格 | 140/70-17 | 140×0.70 = 98 | ✅ 精确吻合 |

### 三个互相独立的验证，这是可信度的来源

1. **转向轴必须落在中面内**（它固定在车架上，与转向角无关）。两根前叉管轴线的
   中点算出来是 **Y = 0.11mm**。这不是拟合目标，是独立的几何约束 —— 它同时证明了
   中面方向和前叉拟合都是对的。
2. **17 吋轮辋是标准件**，胎圈座直径 431.8mm。后轮辋拟合 r=216，360° 覆盖。
   这条不依赖任何轮胎品牌差异，是最干净的绝对尺度验证。
3. **胎侧高度 = 断面宽 × 扁平比**。实测 98mm，140/70 算出来 98mm。

### 三角台偏置：反推出来的

拖曳距的恒等式：

```
trail = Rf·tan(rake) − offset/cos(rake)
95 = 294.8 × 0.4771 − offset / 0.9027   →   offset ≈ 41 mm
```

扫描给了 rake 和 Rf，官方给了 trail，反推出 **偏置 ≈ 41mm** —— R3 这一级的标准值。
三个数闭合。**偏置用卡尺就能量**（前叉管中心 → 转向管中心，完全可及），量到之后
前端几何就齐了，不需要再扫。

### 为什么轴距比官方多 31mm

官方 1380mm 是标称值。实车差异来自链条调节位置 + 后避震状态（车在架子上时摇臂
下垂，后轮轴后移）。**这不是扫描误差** —— 三个尺度验证（轮辋、胎侧、前叉直径）
都通过了。轴距本来就是一个会随调校变化的量，MotoSPEC 里它属于 `WB` 参考测量值。

## 三、拿不到的数，以及为什么

整车带壳，以下**全部被遮挡**，这个扫描里一个也拿不到：

- **转向管孔** —— 埋在整流罩和仪表下面。所以**拖曳距算不出来**（只能靠上面那个反推）
- **避震上下点**（车架端 + 摇臂端）—— 藏在壳子和发动机后面
- **摇臂轴孔** —— 只找到一个很弱的外部候选 (585, 397)，302 个内点，**未验证，不要用**

R3 是**无连杆（linkless）**后避震，按 `src/linkage.js` 的模型只需要 2 个点
（`Frame_Shock_Top_*` + `Drag_To_Swingarm_*`）加摇臂轴。**这 3 个点这次一个都没拿到。**

## 四、下次怎么扫

按价值排序：

1. **拆掉整流罩、油箱、后避震**，扫裸车架 + 裸摇臂。这一条比任何技巧都管用，
   直接解决上面整节的问题。
2. **把车把回正**。这次前轮转过约 24°，导致前轮的同心圆在投影里变成椭圆、
   径向直方图被抹平，前轮心花了很大力气才定准（`steered.py`）。回正就没这个问题。
3. **量一根已知长度做尺度校验**。这次靠 17 吋轮辋侥幸有了一个标准件参考，
   裸车架上没有这种东西。
4. 触地点扫不到（轮胎压在地上），所以"轮胎半径"实际是**轴心到最低可见点**的距离，
   会偏小。要真实滚动半径就直接量，别指望扫描。

## 五、这个目录里的脚本

> **这个目录不是 `batch_fit.py` 的替代品。**
>
> 仓库的主路是 `README.md` §4/§5：CloudCompare 手工分割 → `batch_fit.py`。那条路
> 经过合成真值验证（rake 0.002°、轴距 0.00mm），而且**是连杆坐标的唯一来源**。
>
> `wholebike/` 解决的是另一个问题：**扫完到分割之间的那段空窗**。分割要一小时，
> 而这次扫描是不是废了应该在 2 分钟内就知道 —— 趁车还在架子上。所以这里的工具
> 全部不需要人切，代价是只能拿到前端几何。
>
> 还有一个已知的能力差距：`pipeline.py` 在 **2D 投影**里找圆，所以前轮一转就崩
> （本次实测）。而 `fit_cylinder` 在 **3D** 里拟合切好的表面，**完全不受转向角
> 影响** —— 手工分割那条路没有这个问题。

### `hardpoints_from_segments.py` —— 小 segment 的正确打开方式

第一次真实分割（R3，2026-08）暴露了 `batch_fit` 假设不满足的情形：噪声 ~2mm
的扫描上，25mm 长的轴头小面片 `fit_cylinder` 的**轴向**误差可达几十度（实测同
一根后轴左右两段方向差 61°，但轴线**位置**只差 1.8mm）。方向错 → 轴线∩对称面
的交点飘 → 全链崩。

这个工具的原则：**方向永远不从短圆柱拟合 —— 从物理约束来**：

- 横向轴 = 左右成对 segment 质心连线的共识（三对互洽 0.36°，离群的那对剔除）
- 轮心 = 轴头段 2D 圆心做种子，轮辋 360° 圆在 ±60mm 内精修（盲搜会锁到别的
  环形结构，实测偏 379mm）
- 地面 = 已知胎径的公切线（触地点被架子挡住，"最低可见点"前后偏差不同会把
  地面线拧歪零点几度，直接偏置 rake）
- 每个横向销特征只拟合 2D 圆心；左右各解一遍，差值就是不确定度，直接打印
- 转向轴用 steering_head 全 3D 拟合（弧 358°、长基线，拟合得动），出面外角度
  是自检（收敛到 0.00°）

R3 实测结果（vs 独立参照）：轴距 1406.1（前一天另一次扫描 1411.2）；rake
25.77°（官方 25.0°，扫描时避震全伸展会偏大，方向一致）；yoke offset 31.7mm；
避震眼距 278.7mm；连杆坐标完整导出。位置类不确定度 ±1~2mm（L/R 独立解差
1.2~2.4mm），前轴稍差（±5mm，左右切在了轴的不同台阶上）。

```bash
..\.venv\Scripts\python.exe hardpoints_from_segments.py big_cloud.ply segments/ \
    --front-tyre 297.7 --rear-tyre 314.0 -o out/geometry.json
..\.venv\Scripts\python.exe ..\motospec_export.py out/geometry.json \
    --name "Yamaha R3 (scanned)" --mode linkless
```

**`pipeline.py` 是唯一需要日常跑的** —— 一个文件从头跑到尾，最后强制过 6 条质量门禁：

```bash
cd scan\wholebike
..\.venv\Scripts\python.exe pipeline.py 你的文件.ply          # 单个
..\.venv\Scripts\python.exe pipeline.py a.ply b.ply            # 两个,自动交叉对比
```

任何一条门禁不过，整个结果标成 `RESULTS UNRELIABLE`。**一个看起来像样的错数比
没有数更糟** —— 和 `src/linkage.js` 里不收敛就毒化成 NaN 是同一条原则。

其余脚本是这次分析的分步留档（按执行顺序）：

| 脚本 | 作用 |
|---|---|
| `prep.py` | 去重 + 取最大连通体 + PCA 视图坐标系（其余脚本都 import 它） |
| `diag.py` | 点云体检：重复点、连通分量 |
| `shell.py` | 双层壳检测（局部法向残差分布） |
| `concentric.py` | 在轮子区域找同心圆 —— **圆心不一致就说明轮心没定准** |
| `hubfind.py` | 轮心 = 让径向直方图最"尖"的点（利用轮辋/刹车盘/胎面全部同心） |
| `steered.py` | 转过方向的轮子：交替解 {轮平面} ↔ {轮心} |
| `frame3.py` | 建车辆坐标系：横向取中面法向，"上"取两触地点连线的垂线 |
| `rake2.py` | 前叉搜索。**关键约束：转向轴落在中面内，所以方向只有 rake 一个未知数** |
| `steering2.py` | 前叉管重拟合 → 转向轴 → 偏置；摇臂轴搜索 |
| `final.py` | 出标注图 `r3-final.png` 和 `r3-hardpoints.json` |

跑法（Windows）：

```bash
scan\.venv\Scripts\python.exe scan\wholebike\hubfind.py bike.npy
```

依赖：`numpy scipy open3d matplotlib`（open3d 用于读 binary PLY）。

## 六、踩过的坑（都是真的踩过）

- **环带不是圆柱面。** 按半径分带取点再调 `fit_cylinder`，rms 必然 ≈ 带宽/√12
  （实测 6~8mm，红线是 0.25mm）。必须切真实表面。
- **纯距离判据的 RANSAC 平面检测在扁平物体上完全失效。** 整车点云里"最大的平面"
  全是横切车身的薄板，rms 恰好等于容差/√3。要用法向量。
- **整体镜像配准求对称面不好使**（rms 6mm）—— 真车本来就不对称（排气、边撑、
  链条、转过的前轮）。README 里"用左右成对特征"的办法是对的。
- **球形取点会把整个车头框进去。** 选前叉管必须按"到轴线的径向距离"选，
  不能按到种子点的球形距离选（我这么干过一次，拟合出 132mm 半径的"前叉"）。
- **轮胎标称尺寸算出的直径比实物小 10mm 左右**，对比时要用实际胎径。
