# 开扫前 / 扫完立刻做 —— 检查单

`SCAN_WORKFLOW.md` 讲原理，`README.md` 讲操作，这一份是**扫之前贴在墙上的那张纸**。
每一条后面括号里是"不做会怎样"，全部来自实测踩过的坑（见 `wholebike/README.md`）。

目标：**一次扫完一台车，不拼接。** 拼接不是不能做（`geo-R.ply` 四段拼起来配准得
很干净），但拼接引入的问题需要额外验证，能避开就避开。

---

## A. 车怎么准备（决定上限，做不好后面全白搭）

- [ ] **拆整流罩、油箱、后避震（能拆多少拆多少）**
      （不拆 → 转向管、避震上下点、摇臂轴**一个都拿不到**。这是实测结论，
      不是保守估计。R3 那次整车带壳，连杆级的点一个没拿到。）
- [ ] **车把回正，用胶带/绑带固定住**
      （不回正 → 前轮的同心圆在投影里变成椭圆，**轮辋圆消失**，前轮心定不准，
      连带"上"方向和 rake 全错。R3 那次前轮转了 24°，自动管线直接判 UNRELIABLE。）
- [ ] **车固定在架子上，不能晃**（前后轮都架起来最好）
      （扫描过程中车动了 = 配准漂移，事后无法补救。）
- [ ] **链条调到记录位置，记下刻度**
      （轴距会随链条调节变化。R3 实测轴距比标称多 31mm，就是这个 + 摇臂下垂。）
- [ ] **黑色/抛光/镀铬件喷 AESUB Blue**
      （不喷 → 这些面基本扫不到，或者噪声大到拟合没意义。）

## B. 标记点（如果用标志点模式）

- [ ] 视场内任何时刻 **≥4 个**可见，沿主梁每 40~60mm 一个
- [ ] **随机分布，绝不排成直线或规整网格**（共线无法解算旋转 → 漂移头号来源）
- [ ] 贴在平坦区域，**不贴圆弧边缘/倒角/转角**
- [ ] **周围环境也贴**（架子、地板、背板）—— 很多人漏掉，效果最明显
- [ ] **不贴在要测的特征上**（轴承孔面、避震座端面）—— 会挖掉数据

> 实测对比：几何模式 `geo-R.ply` 点间距 2.80mm、主连通体 97.7%；
> 标志点 `dot-r.ply` 点间距 3.66mm、主连通体 **83.5%**（16.5% 是一块分离的
> 36,540 点大块 = 配准失败的段）。**这台车上几何模式明显更好。**

## C. 扫的时候

- [ ] 关日光灯、避开阳光直射
- [ ] 精度档拉到最高（点间距最小），文件大不是问题
- [ ] 保持在提示的最佳工作距离，别忽近忽远
- [ ] **一次扫完，不分段**（这次的目标）。如果必须分段，段间靠公共标记点对齐，
      并在事后**必须**跑双层壳检测

## D. 导出（这一步最容易废掉整次扫描）

- [ ] **导出点云，不要网格。** 找 Export / 导出，不是 Save / 保存
- [ ] 格式优先级：`.ply` 点云 > `.asc` / `.xyz`（这两种**存不了面片**，最保险）
- [ ] 对话框里若有 点云(Point Cloud) / 网格(Mesh) 选项 → 选**点云**
- [ ] 导完立刻验：

```bash
scan\.venv\Scripts\python.exe scan\inspect_scan_file.py 你的文件.ply
```

必须看到 `✅ PLY **点云**`。看到 `⚠️ 网格` 就回去重导 —— 网格的顶点是重建出来的，
不是原始测量点，rms 会虚低，**所有质量红线因此失效**。

> R3 那次翻遍 Desktop / Downloads 全是 `.stl` 和 `Fused.ply`（4,821,962 顶点 /
> 9,638,773 面片），只有工程目录深处的 `model.ply` 是真点云。

## E. 扫完，车还没拆之前，跑一遍验收

> **先说清楚 `pipeline.py` 和 `batch_fit.py` 是什么关系 —— 不要搞反。**
>
> | | `batch_fit.py`（主路） | `wholebike/pipeline.py`（验收） |
> |---|---|---|
> | 输入 | **你在 CloudCompare 切好的 12 个 segment** | 原始整片点云，不用切 |
> | 输出 | **全部硬点 + MotoSPEC 字段映射** | 只有前端几何（轮心、轴距、rake） |
> | 验证状态 | **对合成真值验证过**：rake 0.002°、轴距 0.00mm | 新代码，无真值验证 |
> | 什么时候跑 | 切完之后，正式提数据 | **导出后 2 分钟，车还在架子上** |
>
> **`batch_fit.py` 才是出数据的路。** `pipeline.py` 存在的唯一理由是它**不需要人切**，
> 所以能在你花一小时做分割**之前**就告诉你这次扫描是不是废了。
> 别拿它替代分割 —— 它在 2D 投影里找圆，前轮一转就崩；
> `fit_cylinder` 在 3D 里拟合切好的表面，**完全不在乎转向角**。

```bash
cd scan\wholebike
..\.venv\Scripts\python.exe pipeline.py 你的文件.ply
```

看最后的 QUALITY GATES：

| 门禁 | 不过说明 | 补救 |
|---|---|---|
| front wheel rim found | 车把没回正 | **车还在架子上,回正重扫** |
| fork midpoint on median plane < 3mm | 中面解错 / 前叉拟合错 | 检查前叉区域点云完整性 |
| two fork tubes agree < 0.20° | 配准漂移 | 重扫 |
| fork radii agree < 0.5mm | 同上 | 重扫 |
| both fork arcs >= 120° | 圆周覆盖不够 | 换角度补扫前叉 |
| main component >= 95% | 有段没配准上 | 重扫,或丢掉那段 |

**全 PASS 才收工。车一拆就回不去了。**

## E2. 验收过了，再按主路做分割

回到 `README.md` §4 和 §5：在 CloudCompare 里把特征一个个切出来存成单独的 `.ply`
（文件名必须用约定关键词，脚本靠名字认类型和左右）。

**切割纪律（血的教训，2026-08 R3 一次全军覆没）：**

- **一个会话切完全部。** 打开母云 → Segment 剪刀 → 框选 → Segment In →
  **立刻 Save** 这个 `.segmented` 子云 → 回来切下一个。
- **任何东西都不要移动/旋转/对齐** —— 不要 Apply Transformation、不要拖动、
  不要 Align/ICP。想把件拖出来端详一下再存？就是这一下,坐标系没了,
  而且**事后看不出来**。
- 那次的 10 个 segment 每个都被分别动过(旋转 9°~93°,平移 97~997mm 不等),
  batch_fit 左右轴合并自检报 39°~64° 夹角。这种数据没有抢救价值。

切完先验坐标系，再跑拟合：

```bash
cd scan
.venv\Scripts\python.exe check_segments.py model.ply segments/
.venv\Scripts\python.exe batch_fit.py --init segments/ -o config.json
.venv\Scripts\python.exe batch_fit.py --run config.json
```

`check_segments.py` 验证每个 segment 的点真的存在于母云里(p95 < 1mm)。
不过就别往下跑 —— batch_fit 会给出一堆能算但全错的数。

**分割不是可选步骤。** 拆干净之后能切出来的那 12 个特征，是连杆坐标的**唯一来源**
（见 `docs/research/linkage-coords.md`）。`pipeline.py` 一个都给不了。

## F. 扫描给不出、必须另外量的

这几个用卡尺几分钟就好，别指望扫描：

- [ ] **三角台偏置**（前叉管中心 → 转向管中心的垂直距离）
      —— 拖曳距的最后一块拼图。R3 反推出来约 41mm，官方 trail 95mm 正好对上
- [ ] **前后轮实际滚动半径** —— 触地点扫不到（轮胎压在地上），扫出来的"半径"
      是轴心到最低可见点，会偏小
- [ ] **簧下质量、弹簧刚度、行程** —— 几何扫描本来就不含这些
- [ ] 一段已知长度做**绝对尺度校验**（裸车架上没有 17 吋轮辋这种标准件可蹭）
- [ ] **前叉总长、避震眼距** —— 不 gate 任何当前计算,但它们是**将来换件时算
      Delta 的唯一基准**(Fork_Length_Delta = 新长 − 记录值)。漏了当下不坏,
      坏在半年后换件那天。趁东西在手边顺手记,口径写清(含不含叉盖)
